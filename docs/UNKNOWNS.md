## Chargeback history in Cosmos DB (ADR-0044)

| ID | State | Question / evidence |
| --- | --- | --- |
| AUD-C1 | RESEARCHED | What does a daily history write cost? A write of a 1 KB item costs about 5 RU and a point read 1 RU; indexing every property raises write cost, and excluding unused paths lowers it ([request units](https://learn.microsoft.com/en-us/azure/cosmos-db/request-units), [optimize reads and writes](https://learn.microsoft.com/en-us/azure/cosmos-db/optimize-cost-reads-writes), [indexing policy](https://learn.microsoft.com/en-us/azure/cosmos-db/index-policy), retrieved 2026-10-25). One document per day, chargeback ID, group, classification, person and model is under 1 KB. Writing every changed document every minute would cost, for a hypothetical 1,000 active people with 2 models each over 8 hours, 1,000 x 2 x 480 x 5 = 4.8 million RU a day. Decision: an open day's document is rewritten only when its totals changed and the stored copy is at least 60 minutes old, plus one closing write: at most 25 writes per document and day (about 0.25 million RU a day in the same example). The container indexes only the queried fields. |
| AUD-C2 | RESEARCHED | Partition key? A logical partition holds at most 20 GB ([partitioning](https://learn.microsoft.com/en-us/azure/cosmos-db/partitioning-overview), retrieved 2026-10-25). Query patterns: one month for every group (the CSV export, the main read), one group over months, one person over months. `/month` (`YYYY-MM`) makes the export a single-partition query; the other two fan out to one partition per month, bounded by the export's maximum range. Writes of a minute go to one or two months; with the write limit of AUD-C1 that is far below a physical partition's 10,000 RU/s. A month of the example (1,000 people x 2 models x 31 days, under 1 KB each) is about 62 MB. `/scopeId` would spread writes but make the export a cross-partition query every time. |
| AUD-C3 | RESEARCHED | Late ledger rows. Log Analytics ingestion usually takes 20 seconds to 3 minutes and has no upper bound ([ingestion time](https://learn.microsoft.com/en-us/azure/azure-monitor/logs/data-ingestion-time), retrieved 2026-10-25). The reconciler already reads the whole current month every run (`src/reconciler/run.ts`), so every open day of the month is recomputed from that read without another query. A day closes `closeAfterDays` (1-7) whole days after it ends. While days of the previous month are still open (the first `closeAfterDays` + 1 days of a month), one extra ledger query reads only the previous month's open tail. |
| AUD-C4 | RESOLVED | Idempotency. The document id is the SHA-256 of `day`, chargeback ID, project, classification, person and model (Cosmos ids may not contain `/`, `\`, `?` or `#`, and a chargeback ID may contain `/`). Re-running a minute upserts the same ids with the same totals; a content hash of the totals and the closed flag decides whether a write is needed (`src/reconciler/history.ts`). |
| AUD-C5 | RESOLVED | Finalisation and retention. A closed day is frozen as a whole: no document of it is written again except to close one still open with unchanged totals, so a key that moves after the close is refused (`historyClosedRefused`, ADR-0044 decision 3). An open document is never replaced by one with fewer requests (a partial read or rows that aged out). Log Analytics retention can be as low as 4 days ([data retention](https://learn.microsoft.com/en-us/azure/azure-monitor/logs/data-retention-configure), retrieved 2026-10-25); the staged driver accepts 30 days or more (`audit.workspaceRetentionDays` 30-730; the example's `stage1.retentionInDays` is 30), and `closeAfterDays` is at most 7, so every day closes well inside the retention. With 30 days, the first hours of day 1 of a 31-day month can age out on the 31st: a day already covered is unaffected (closed days are not rewritten, an open day's total never falls), but a first history run on the 31st backfills day 1 from what remains and covers it. Blast radius: that one day of the first month may be low; detector: compare it with the archive (ADR-0043) or the budget state of that month. |
| AUD-C6 | RESOLVED | Tags at write time or report time? The chargeback ID is the one the gateway stamped on each request (`chargebackId` in `analytics/ledger.kql`), the same value the Log Analytics report groups by, so history keeps the request-time value. The admin-defined column heading (`userTagSettings`, ADR-0037) is applied when the export is read, so renaming the label changes old exports' heading but not their values. |
| AUD-C7 | ASSUMED | Container time to live. With `defaultTtl` set, items expire that many seconds after their last write (`_ts`) ([time to live](https://learn.microsoft.com/en-us/azure/cosmos-db/time-to-live), retrieved 2026-10-25). `ttlDays` null means no expiry. An item's own `ttl` overrides `defaultTtl` when the container has one, `-1` never expires, and an expired item is no longer returned by queries even before it is deleted (same page). ADR-0044 decision 9: every document of a month carries a `ttl` counted to one instant, `ttlDays` after the month ends, and the coverage record (`ttl: -1`) keeps the earliest such instant in `expiresAt`; the export refuses days within one day of it (`history_expired`). Changing `ttlDays` applies to documents written after the change (a closed month is not written again and keeps its expiry); Stage 2's `defaultTtl` then only applies to items without their own `ttl`. Blast radius: a shorter `ttlDays` does not delete older closed months sooner; delete them by hand if needed. Detector: `history_expired` names the month's `expiresAt`. |
| AUD-C8 | ASSUMED | History totals are the reconciler's: list price from the rate card in force at each request, as the Log Analytics report. Columns that need per-request detail the reconciler does not read (cache savings, duplicate copies, trace mismatches, failed requests) are empty in history rows. Blast radius: those columns of months older than the Log Analytics window are blank. |
| AUD-C9 | RESOLVED | Can a ledger row move between history documents? Yes: the ledger joins the LLM log with the gateway log, ingested separately, so a request can first appear without its trace (no chargeback ID or person) and gain them a minute later (council review 2026-10-25, reproduced with `buildDailyDocuments`). Planning per day zeroes the document the row left, and compares day totals for the never-lower guard; lowering writes run before raising ones, so an interrupted run undercounts until the next run and never double-counts (`tests/reconciler-history.test.ts`, `tests/reconciler-history-run.test.ts`). Residual: a day whose total falls (a row later classified as refused before any backend call) is refused and stays open; the run line counts it as `historyShrinkRefused`. |
| AUD-C10 | RESOLVED | Several reconciler instances. History runs under its own lease (`ccof-chargeback-history`, taken after the budget lease is released, ADR-0044 decision 7), so history runs are exclusive, but each host caches summaries for 60 minutes. Writes are conditional (create, or replace If-Match the cached etag); a 409 or 412 drops that month's cache and fails history for the run (`history_conflict`), and the next run re-reads (`src/reconciler/history-run.ts`, `src/reconciler/azure.ts`). |
